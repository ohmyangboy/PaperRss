# Issue #3：文章高能滚动条（TOC Rail）规格

- **Status**: `accepted`
- **原始 Issue**: [#3 希望能够加入目录的功能](https://github.com/ohmyangboy/PaperRss/issues/3)
- **提交者**: @cheemskc
- **状态**: 已批准开发
- **类型**: UI/UX 功能增强（Feature Request）

## Problem Statement

长文章、技术文档和翻译后的文章在阅读器中纵向距离很长。用户只能依靠系统滚动条或触控板连续滚动，难以快速判断文章结构、回到某一章节或定位自己当前所处的位置。传统目录面板会占用阅读宽度，而没有结构化标题的文章又不能因为缺少标准标题而完全失去导航能力。

用户需要一种类似 ChatGPT 的紧凑型“高能滚动条”：它贴近阅读区边缘，平时只显示文章结构的短线，当前阅读位置明显高亮，悬停时给出章节预览，点击或拖拽即可快速导航，同时保留系统滚动条在短文和无法建立可靠目录时的原生行为。

## Solution

在 macOS 文章阅读 WebView 的右侧增加本地生成的 TOC Rail。它根据当前文章 DOM 在本地建立稳定的锚点集合，并随滚动位置更新当前项。文章足够长且至少有三个可用锚点时显示 TOC Rail，并隐藏该 WebView 的原生滚动条；不满足条件时移除 TOC Rail，恢复 macOS/WebKit 原生滚动条策略。

TOC Rail 的锚点优先来自文章标题，必要时从可见长段落生成退化锚点。它不依赖服务器、上传文章内容或新增持久化数据。标题、预览和当前位置均来自当前 WebView 的本地 DOM，因此文章翻译、摘要展开、字体变化和窗口大小变化后仍能重新计算并保持可用。

## User Stories

1. 作为 macOS 文章阅读用户，我希望在足够长的文章旁看到紧凑的结构导航，以便快速理解文章长度和章节分布。
2. 作为 macOS 文章阅读用户，我希望当前阅读位置对应的锚点被高亮，以便不用连续滚动也能知道自己在文章中的位置。
3. 作为 macOS 文章阅读用户，我希望悬停在锚点上能看到章节标题和正文摘录，以便在跳转前判断该位置是否是我要找的内容。
4. 作为 macOS 文章阅读用户，我希望点击锚点后平滑跳到对应内容，并在阅读区顶部保留安全间距，以便落点不会被窗口内容遮挡。
5. 作为 macOS 文章阅读用户，我希望拖动当前高亮指示器能连续浏览全文，以便快速定位到文章的大致位置，而不必逐个点击章节。
6. 作为 macOS 文章阅读用户，我希望鼠标滚轮、触控板、空格翻页和已有的滚动位置恢复继续工作，以便新导航不改变原有阅读习惯。
7. 作为 macOS 文章阅读用户，我希望短文章仍使用系统滚动条，以便不为没有必要的目录增加界面噪音。
8. 作为 macOS 文章阅读用户，我希望没有足够结构信息的文章仍能通过长段落获得有限导航，以便非标准 HTML 文章也能受益。
9. 作为 macOS 文章阅读用户，我希望标题相同的文章大标题和第一个正文标题不会产生重复锚点，以便导航不显示重复入口。
10. 作为 macOS 文章阅读用户，我希望大量标题不会让滚动条变成无法操作的密集列表，以便在长文中仍能分辨和命中各个位置。
11. 作为 macOS 文章阅读用户，我希望文章翻译后导航文字同步反映当前语言，以便预览与正在阅读的内容一致。
12. 作为 macOS 文章阅读用户，我希望窄窗口中预览卡片不会遮住不可用区域或超出窗口，以便三栏布局、Zen Mode 和窄 detail 宽度下仍能阅读。
13. 作为 macOS 文章阅读用户，我希望系统“减少动态效果”设置生效，以便需要时获得即时跳转而不是平滑动画。
14. 作为键盘或辅助功能用户，我希望锚点具有可聚焦的命中区域、可读标签和键盘激活方式，以便不依赖精确鼠标操作也能导航。
15. 作为本地优先用户，我希望文章内容、锚点和预览只在本机 WebView 内处理，以便此功能不引入遥测、设备标识、附件或后台上传。
16. 作为应用维护者，我希望 TOC Rail 只影响 macOS 文章阅读器，以便 iOS 和 Core 层的既有行为、数据模型和接口保持不变。
17. 作为应用维护者，我希望文章 DOM、翻译、摘要和窗口变化触发幂等重算，以便重复加载不会产生重复轨道、监听器或错误的滚动状态。

## Implementation Decisions

- **平台和入口**：功能只注入 macOS 文章阅读 WebView 的阅读态，不扩展到 iOS，不修改 Core 模型、持久化结构、同步协议或公开 API。实现作为阅读 WebView 的私有 DOM 控制器和样式注入，不新增 Swift/JavaScript Bridge 消息协议或遥测入口。
- **启用条件和退化**：仅当文档 `scrollHeight` 大于 `2 × clientHeight`，且最终锚点数量不少于 3（包含合成文章大标题）时启用。条件不满足、文档高度暂不可用或锚点无法建立时，移除轨道状态并恢复系统滚动条；不得出现系统滚动条与 TOC Rail 同时承担同一纵向导航的双滚动条。
- **锚点来源**：合成文章大标题始终作为首锚点。随后按 DOM 顺序提取正文中的 H1–H6，并保留标题层级用于语义排序和辅助信息。正文第一个标题与合成大标题在忽略大小写、空白和常见标点后同名时去重，保留一个首锚点。不得把仅靠 CSS 加粗、但没有可靠标题标签的文本当作标题。
- **无标题文章的退化**：当标题不足以形成三个锚点时，从正文可见叶子块中选择长度至少约 6 行且不少于 80 个字符的长段落，按文档位置均匀补足锚点。退化锚点的名称使用首句，预览摘录使用其余正文；不足三个锚点时仍回退到系统滚动条。
- **锚点稳定性和压缩**：锚点在一次文章加载后按文档位置固定，不因滚动而重新抽样或更换。候选超过 18 个时固定压缩：保留首尾、优先保留高层级语义标题，并按全文位置分区均匀选择其余候选，保证加载后结果稳定且轨道可操作。窗口尺寸、正文 DOM、字体、翻译或摘要变化导致结构变化时，整体幂等重算并重新判断启用条件。
- **轨道布局**：轨道固定在阅读区右边缘、垂直居中；高度按锚点数量增长，使用 `clamp(120px, anchorCount × 18px, min(55vh, 360px))` 的效果范围。每个普通锚点显示等长浅灰短线；当前项显示更深、更长的线。线长不用于表达 H1–H6 层级，避免层级导致视觉跳动。
- **交互命中和当前项**：线条只是视觉表达，锚点按钮和轨道具有至少约 28px 的可命中/可聚焦区域。滚动时依据锚点在视口中的位置更新当前项；轨道本身不拦截正常滚轮、触控板、空格翻页或已有的位置恢复。当前深色指示器同时作为拖拽入口。
- **悬停预览**：鼠标悬停约 150ms 后，在轨道左侧显示该锚点的预览卡片；标题最多两行，正文摘录最多四行，卡片宽度上限约 360px，并在窄窗口中限制为实际可用宽度。预览从当前 DOM 文本读取，因此翻译或正文展开后显示当前内容。离开轨道/卡片或按 Escape 时关闭；拖拽过程中关闭预览。
- **点击和拖拽**：点击锚点将目标内容滚动到阅读区顶部安全边距下方约 24px。默认使用平滑滚动；检测到系统“减少动态效果”时改为即时跳转。拖动当前指示器使用 pointer capture，将轨道内的纵向比例连续映射到全文可滚动范围；释放后重新计算并高亮落点。点击、拖拽和预览不得改变文章内容或阅读状态之外的持久化数据。
- **动态和并发行为**：控制器安装、重算和清理必须幂等，避免重复 DOM、监听器和样式状态。resize、正文内容变化、翻译切换、摘要展开和字体缩放完成后重新计算；计算期间若文档暂不可用，应保持系统滚动行为并在下一次稳定事件后重试。预览和跳转必须使用当前文章实例，不能串到已离开的文章。
- **辅助功能和本地化**：锚点提供可读的辅助功能标签、键盘聚焦和键盘激活；预览是辅助信息，不依赖颜色或线长才能理解当前位置。新增界面文案遵循现有本地化入口；文章标题、章节标题和摘录直接使用 DOM 当前语言，不改变独立的 UI 语言与 AI 输出语言设置。
- **隐私边界**：锚点解析、文本摘录、状态计算和滚动映射全部在本地 WebView 完成；不发送文章内容，不保存锚点，不生成设备 ID，不增加附件、上传、同步或静默遥测。

## Testing Decisions

- **主要测试 seam**：优先在最高层通过 macOS WebView 中用户可观察的 DOM、轨道状态和滚动行为进行 JavaScript 行为测试；测试只断言外部行为（是否显示/隐藏、锚点顺序、当前项、预览文本、滚动落点、拖拽映射和动态重算），不绑定内部函数名称或具体 DOM 实现。该 WebView 行为 seam 作为功能的单一主要测试 seam。
- **解析和退化场景**：覆盖合成大标题、H1–H6 顺序、同名去重、CSS 加粗不识别、长段落阈值、均匀补足、首句命名、少于三个锚点时恢复系统滚动条，以及超过 18 个候选时首尾/高层级/分区压缩和稳定顺序。
- **交互场景**：覆盖超过两屏的启用阈值、普通滚动更新当前项、悬停延迟和标题/摘录截断、点击的 24px 安全偏移、减少动态效果下即时跳转、pointer capture 连续拖拽、释放后的当前项、Escape 关闭预览和键盘激活。
- **动态场景**：覆盖 resize、正文 DOM 变化、翻译切换、摘要展开、字体缩放、重复加载与清理；确认不会重复插入轨道或监听器，条件失效时原生滚动条恢复。
- **平台隔离检查**：通过静态检查确认注入点仅在 macOS 路径，iOS 路径、Core 层和现有 WebView Bridge 协议未被扩展。该检查用于守住平台边界，不替代运行时测试。
- **构建和运行验证**：运行现有 Node 行为测试、项目 Swift 测试及 macOS 桌面产品构建；在真实 macOS UI 中验证三栏、Zen Mode、约 400px detail 窄宽和宽窗口，以及翻译、摘要、字体缩放、无标题/重复标题、超多标题、触控板、键盘和位置恢复。分别记录自动化、构建和真实 UI 的验证边界。

## Out of Scope

- iOS、iPadOS 或其他非 macOS 阅读界面的目录导航。
- 独立的侧边栏目录树、移动端底部按钮、Sheet/Popover 目录面板、折叠开关或用户偏好持久化。
- 修改文章 HTML 清洗规则以识别 CSS 加粗伪标题，或为不规范文章引入通用语义修复器。
- Core 数据模型、同步、CloudKit、AI 输出、阅读进度持久化、网络接口、公开 API 或 Swift/JavaScript Bridge 协议变更。
- 文章内容上传、附件自动收集、遥测、设备标识和其他诊断数据采集。
- 重新设计系统滚动条、改变全局 macOS 滚动条偏好，或声称已完成发布、签名、设备和线上验证。

## Further Notes

- 本规格已获维护者批准开发，作为后续实施工单和实现验收的权威公开草案。
- “高能滚动条”是交互定位名称，最终 UI 文案不需要显示该名称。
- 当 WebView 内容没有稳定高度、标题文本为空或动态内容仍在加载时，应优先保持可用的系统滚动行为，避免显示误导性或不可点击的轨道。
- 真实 macOS UI 验证用于确认 WebKit 滚动条隐藏、鼠标/触控板命中、窗口边界和减少动态效果行为；它不能由 Node 测试或 Swift 构建替代。
