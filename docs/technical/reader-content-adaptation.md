# Reader 正文结构保留与内部适配

- **Status**: implemented
- **Issue**: https://github.com/ohmyangboy/PaperRss/issues/31

## 问题与范围

段落标注从纯文本重建 HTML，丢失混合段落中的图片、链接与强调。修正 Core 展示处理，将段落索引和 HTML 注解共用结构规则，Renderer 统一调用，macOS/iOS Coordinator 不再预加工正文。

## 设计

内部结构适配按固定顺序运行：明确连续 br 的普通段落可保留 HTML 片段拆分；其他结构原样保留。不以站点识别，不引入依赖、动态插件或网络行为。不改变图片 URL 策略。无法安全拆分时保留完整安全块。纯文本只用于 AI 提取，不能反向充当展示正文。

## 验收

完整准备到 Renderer 链路保留媒体、链接、强调、顺序及段落映射；源码格式换行不改变内容。验证原文与初始/增量翻译契约、旧译文匹配、结构不完整时的保守处理。运行 Core、feature、Web/Bridge、macOS 构建和真实 App 观察。验证使用备份后的隔离数据，发布独立执行。

## 已实现的接口与适配规则

`ReaderDocumentRenderer.renderDocument` 直接接收 `PreparedArticle`、`translations` 与 `pendingTranslationIDs`，生成已完成段落标注的最终 HTML。外部不再传入自行重写的 `bodyHTML`。原文模式以空译文数组进入同一流程；增量翻译继续使用既有 Bridge。

`ArticleExtractor` 内部的 `ReaderBlockAdapter` 依次尝试：

1. `explicitBreakParagraph`：只在完整普通段落中按直属、连续的 `br` 拆分，保留原始 HTML 片段、属性及媒体位置。单个 `br` 后的源码换行不参与拆分。
2. `preservedBlock`：保留结构块、嵌套行内结构、纯媒体片段及无法安全拆分的内容。允许翻译单元稍大，不以纯文本替换正文。

新增策略应返回安全 HTML 片段或声明不匹配。非布局标签及其属性顺序、规范化文本须与输入一致，否则回退到原块。允许改变的分段标记仅限 `p` 与 `br`；媒体及链接不得改写。

段落索引与展示 HTML 共用上述结构适配。旧译文只有 ID 与原文均匹配才参与展示、缓存复用、请求排除与完成状态计算；按原文缓存的翻译仍可复用。

## 扩展与约束

这是引擎内部的结构适配接口，不提供动态插件加载。站点地址不参与匹配。现有格式规范化、懒加载地址选择、图片安全清洗及 WebKit 有限重试继续各自承担原职责。

当前扫描器只处理能确认边界的安全片段，不是完整 HTML DOM parser。复杂或不完整结构保守保留；未来若需支持无法安全处理的树变换，应另行评估 HTML parser，而非堆叠站点补丁。

新增适配应补充最小结构 fixture，经过准备到最终 Renderer 的真实路径，检查图片顺序、链接、强调、段落 ID 与译文位置；仅比较准备阶段图片数量不足以验收。
