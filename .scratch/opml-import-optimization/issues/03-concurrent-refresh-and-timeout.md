# 03 — 后台受控并发 Refresh 与单源 10 秒超时防护

**What to build:**
重构订阅源 Refresh 执行引擎。将原本在主线程运行的单线程串行循环改为后台 TaskGroup 线程池（限制最大并发数为 6）。同时为每一个源在网络层包覆 10 秒超时控制，并将获取到的数据分批写回主线程，保障主线程 UI 帧率流畅，避免界面假死。

**Blocked by:** 02 — OPML 导入增量刷新隔离

**Status:** completed

- [x] Feed 刷新通过 TaskGroup 并发执行，最大并发度限制为 6，显著缩短批量导入的刷新总耗时。
- [x] 单个响应缓慢或无法连接的订阅源在 10 秒后自动超时并被忽略，不会挂起后面的订阅源或阻塞 App。
- [x] 在批量刷新过程中，侧边栏/状态栏实时更新进度，主界面滑动与文章阅读完全不受卡顿影响。
